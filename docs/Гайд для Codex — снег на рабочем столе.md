# Гайд: как с Codex (ChatGPT) сделать «снег на рабочем столе» для Windows

Этот файл — пошаговый план для ИИ-агента (Codex / ChatGPT) и для человека, который им управляет.
Его можно целиком вставить в Codex как задание, а потом идти по этапам: **один этап — один запрос**,
после каждого этапа — запуск и проверка глазами.

Итог: лёгкая программа для Windows 10/11, где по экрану идёт снег, он копится сугробами
на окнах и панели задач, его можно смахивать курсором, лепить снеговиков; есть гирлянды,
снегоуборщик, живые обои. Клики проходят сквозь снег. Нагрузка — около 0,5 % процессора.

> Делайте своё: своё название, свои рисунки и сцены. Не копируйте чужой бренд, тексты и картинки.

---

## 0. Что сказать агенту в самом начале (вставить как первый запрос)

```
Ты — опытный разработчик Windows-приложений на C#. Мы делаем программу «снег на рабочем столе»
для Windows 10/11 (x64). Требования:
- .NET 10 (или 8 LTS), C#, без WinForms/WPF — чистый Win32 через P/Invoke.
- Рисование только на видеокарте: Direct3D 11 + Direct2D + DirectComposition
  (NuGet: Vortice.Direct3D11, Vortice.Direct2D1, Vortice.DirectComposition).
- Прозрачные окна поверх всех окон, клики проходят насквозь.
- Цель по нагрузке: < 1 % CPU в простое со снегом на 2 мониторах.
- Работаем по этапам. После каждого этапа: собери (dotnet build), перечисли что сделал,
  что не проверено, и жди моей обратной связи. Не делай несколько этапов сразу.
- Комментарии в коде — короткие и по делу. Без лишних абстракций.
```

Дальше — этапы. В каждом этапе есть: **что сделать**, **как устроено** (ключевые решения,
которые экономят часы), **как проверить**, **типичные ошибки**.

## Этап 1. Прозрачное окно со снегом на всех мониторах

**Что сделать**
- Консольный проект → `OutputType=WinExe`, `AllowUnsafeBlocks=true`, манифест с
  `dpiAwareness = PerMonitorV2`.
- На каждый монитор (`EnumDisplayMonitors` + `GetMonitorInfo`) — своё окно-оверлей размером с монитор.
- Падающие снежинки, иконка в трее с меню, пауза, 3 режима снегопада, ветер, горячие клавиши,
  настройки в `%APPDATA%\<Имя>\settings.json`.

**Как устроено**
- Окно: `WS_POPUP` + `WS_EX_TOPMOST | WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_TOOLWINDOW |
  WS_EX_NOACTIVATE | WS_EX_NOREDIRECTIONBITMAP`, затем `SetLayeredWindowAttributes(hwnd, 0, 255, LWA_ALPHA)`.
  В оконной процедуре `WM_NCHITTEST` → `HTTRANSPARENT`. Так клики уходят в окна под снегом.
- Графика: одно устройство D3D11 (`BgraSupport`) → D2D device context → DirectComposition device.
  Для окна: `CreateSwapChainForComposition` (B8G8R8A8, `AlphaMode.Premultiplied`, `FlipSequential`,
  2 буфера) → `CreateTargetForHwnd` → visual с этой цепочкой. Это быстро: никаких
  `UpdateLayeredWindow` и копирований через процессор.
- Снежинки — **один спрайт-атлас** (картинки снежинок рисуются кодом в массив пикселей при запуске:
  мягкая точка, круглая, 2 вида кристаллов) и **`ID2D1SpriteBatch`** (`DrawSpriteBatch`) —
  тысячи снежинок за один вызов. Прозрачность через цвет спрайта `(a,a,a,a)` (premultiplied).
- Параллакс: каждой снежинке случайная «глубина» z (дальние мельче, медленнее, бледнее),
  покачивание синусом, ветер с порывами.
- Главный цикл в одном потоке: `PeekMessage` → кадр → ожидание через
  `CreateWaitableTimerEx(CREATE_WAITABLE_TIMER_HIGH_RESOLUTION)` + `MsgWaitForMultipleObjectsEx`
  (окна остаются отзывчивыми, ожидание точное). На паузе — просто ждать сообщений, кадров не рисовать.
- Иконка трея: `Shell_NotifyIcon`, меню через `TrackPopupMenuEx`. Обрабатывайте сообщение
  `TaskbarCreated`, чтобы иконка вернулась после перезапуска Проводника.
- Окна-оверлеи раз в 2 секунды поднимайте `SetWindowPos(HWND_TOPMOST)`, иначе панель задач
  иногда оказывается выше.
- `WM_DISPLAYCHANGE`/`WM_DPICHANGED`/`WM_SETTINGCHANGE` → пересоздать оверлеи (с задержкой ~0,5 с).
- Потеря видеоустройства (обновление драйвера) → ловить исключение и пересоздать всё.

**Как проверить**
- Снег на обоих мониторах, клик сквозь снег попадает в окно под ним.
- Замер CPU в PowerShell: `TotalProcessorTime` процесса за 20 с → цель < 1 % от машины.

**Типичные ошибки**
- Горячие клавиши Ctrl+Alt+стрелки заняты драйвером Intel (поворот экрана) — берите
  Ctrl+Alt+Shift+...
- Запуск собранного exe без `DOTNET_ROOT`, если .NET стоит не в Program Files, — exe не стартует.

## Этап 2. Сугробы на окнах, панели задач и внизу экрана

**Что сделать**
- Снег копится на верхних краях окон, на панели задач и у нижнего края монитора.
- Сугроб едет вместе с окном. Свернули/закрыли окно — снег с него падает. Потрясли окно — часть слетает.

**Как устроено**
- **Отслеживание окон:** `EnumWindows` (порядок = Z-порядок сверху вниз), фильтры:
  видимое, не свёрнутое, не `WS_EX_TRANSPARENT`, не свои окна, не `Progman/WorkerW`,
  не «cloaked» (`DwmGetWindowAttribute(DWMWA_CLOAKED)` — окна других рабочих столов).
  Границы — `DWMWA_EXTENDED_FRAME_BOUNDS` (без невидимых рамок).
- **Не сканировать каждый кадр!** Поставьте `SetWinEventHook` (OUTOFCONTEXT) на события
  LOCATIONCHANGE, SHOW/HIDE/DESTROY/REORDER, FOREGROUND, MINIMIZE, CLOAKED/UNCLOAKED
  (только `idObject==0`) и пересканируйте только после события + страховочно раз в секунду.
  Это сократило обход с 0,5 мс до 0,02 мс за кадр.
- **Сугроб = карта высот** по колонкам шириной ~3 px, привязанная к левому краю окна
  (поэтому двигается с окном бесплатно). Снежинка, пересёкшая поверхность, добавляет «площадь»
  в несколько колонок (треугольный разброс). Ограничение высоты + скругление к краям окна.
  «Осыпание»: если соседние колонки различаются сильнее порога, перекладывать разницу.
- **Видимость:** для каждого края считать видимые отрезки — вычесть прямоугольники окон,
  которые выше по Z и перекрывают полосу над краем. Снег ложится и рисуется только там.
- **Отрисовка сугробов — главная ловушка производительности:**
  - D2D переразбивает `PathGeometry` на треугольники при каждом `FillGeometry` — дорого.
    Используйте **`CreateFilledGeometryRealization`** (кэш на видеокарте).
  - Перестраивайте форму, только когда изменение заметно (≥ 0,5 px), и синхронно для всех
    сугробов не чаще ~4 раз в секунду (во время смахивания — 30).
  - Вынесите сугробы в **отдельный слой** DirectComposition (вторая swap-chain под снежинками)
    и перерисовывайте его только когда «подпись» (видимые отрезки + версии форм) изменилась.
  - Итог: сугробы почти не добавляют нагрузки.
- **Тряска:** считать скорость окна между сканированиями; тряска = несколько смен направления
  быстрой скорости за короткое время. Мгновенный прыжок окна (развернуть, прилепить к краю)
  тряской не считать.

**Как проверить**
- Подвинуть окно медленно — сугроб едет и не осыпается. Потрясти — часть слетает.
  Свернуть — сугроб падает. Развернуть/восстановить — ничего не должно слетать.

## Этап 3. Варежка, лопата, снежки и снеговики

**Что сделать**
- Курсор сметает снег (варежка — немного, лопата — всё). «Убрать весь снег».
- Режим лепки: тянешь по сугробу — катится и растёт шар; шар можно взять и положить на другой
  → снеговик (глаза, морковка, улыбка, пуговицы, руки-ветки).

**Как устроено**
- Курсор: `GetCursorPos` каждый кадр (хуки не нужны). Курсор = круг, движущийся по отрезку
  между кадрами. Для каждой колонки сугроба считать пересечение круга с колонкой;
  варежка снимает долю, растущую со скоростью движения (медленный проход лишь чешет верх).
- **Как выглядит смахнутый снег — самое важное для «вау»:**
  - НЕ делайте облако мелких частиц и НЕ делайте угловатые твёрдые куски — выглядит дёшево.
  - Хорошо смотрится так: срезанный за проход снег копится доли секунды и отпускается одним
    **мягким комом** — группа из 6–9 перекрывающихся эллипсов («пух») с той же заливкой, что
    сугробы, одной общей тенью. Ком плавно падает с ускорением (гравитация + мягкая
    предельная скорость), слегка вытягивается на скорости, чуть «дышит», при касании сугроба
    ниже — вливается в него (добавить площадь в колонки по ширине кома).
  - Большие порции делить на несколько комьев, слишком маленькие — не показывать.
  - Не давайте кому сразу приземлиться обратно на тот сугроб, с которого он слетел (~0,3 с).
- **Режим лепки:** окна-оверлеи временно убирают `WS_EX_TRANSPARENT` и в `WM_NCHITTEST`
  отвечают `HTCLIENT` (+ курсор-рука, `WM_MOUSEACTIVATE` → `MA_NOACTIVATE`). Кнопку мыши
  читать `GetAsyncKeyState`. Выход — Esc / правая кнопка / автоматически через 2 минуты.
- Шары и снеговики «сидят» на сугробе окна (хранить ключ сугроба + смещение) и едут с окном;
  если окно пропало — падают. Рисовать примитивами D2D (эллипсы, радиальный градиент).

## Этап 4. Гирлянды и снегоуборщик

**Гирлянды**
- Провод провисает между крючками вдоль верхнего края окон и панели задач — он статичный,
  рисуется в слой сугробов. Лампочки анимируются — в слой снежинок, тем же спрайт-батчем.
- Свечение лампочки: большой мягкий спрайт с **почти нулевой альфой** в premultiplied-цвете
  (получается аддитивное свечение) + яркая «колба».
- Режимы: горят, мигают, бегут волной, мерцают (у каждой лампочки свой ритм), переливаются
  радугой, бегущий огонёк. Формы: классические, шарики, звёздочки, сосульки, ретро-лампы.
  Размер лампочек — настройка.

**Снегоуборщик**
- Выезжает, когда сугроб на панели задач заполнен больше чем наполовину (перерыв 40 с,
  чередовать сторону). Едет по краю, плавно разгоняется, с тяжёлой кучей медленнее.
- Отвал снимает почти всё (оставить тонкий слой — реалистичнее). Куча перед отвалом —
  путь с бугристой «бурлящей» верхушкой; размер куча меняет плавно (сглаживание).
  Излишек иногда отваливается мягким комом вперёд. Машина слегка покачивается.
- Машины — векторные рисунки примитивами D2D в «дизайн-единицах» (отвал в точке 0,0,
  зеркалить трансформом по направлению): трактор, ретро-трактор, снегоход, пингвин с лопатой.
- «Своя картинка»: выбор файла (`GetOpenFileName`), загрузка через WIC (есть внутри
  Vortice.Direct2D1), уменьшение до ~384 px; если фон однотонный — заливка от краёв в прозрачность.
  Картинку не зеркалить (иначе текст наоборот). Копировать файл в папку настроек.
- Обрезать отрисовку по видимым отрезкам края (окна могут закрывать панель задач).

## Этап 5. Живые обои за значками рабочего стола

**Как встроиться под значки (не меняя обои пользователя)**
- `FindWindow("Progman")`, отправить `0x052C` (`SendMessageTimeout`).
- **Windows 11 24H2 и новее:** значки (`SHELLDLL_DefView`) — дочернее окно Progman. Своё окно
  сделать дочерним Progman (`SetParent`), стиль `WS_CHILD`, `WS_EX_LAYERED` + alpha 255,
  и поставить в Z-порядке сразу под `SHELLDLL_DefView` (`SetWindowPos(hwnd, defView, ...)`).
- **Windows 10 / ранняя 11:** найти верхний `WorkerW`, внутри которого `SHELLDLL_DefView`;
  следующий `WorkerW` после него — наш родитель.
- Координаты переводить `ScreenToClient(parent)`. Содержимое — DirectComposition, как у оверлеев.
- Выключение: уничтожить окна и `RedrawWindow(progman, ..., RDW_INVALIDATE|RDW_ERASE|RDW_ALLCHILDREN)`.
- Если Проводник перезапустился — окна исчезнут, пересоздать.

**Сцены** (рисовать кодом, единица = 1 % высоты экрана)
- Статичное (небо, горы, ели, дом) — один раз в битмап; каждый кадр: битмап + живое
  (свет в окнах мерцает, дым из трубы — «бесконечные» затухающие клубы по формуле от времени,
  гирлянда, мерцающие звёзды). 15 кадров/с хватает.
- Не анимировать, если монитор целиком закрыт окнами.
- **Ловушка:** не создавать кисти/градиенты в каждом кадре — это заметно грузит процессор.

## Этап 6. Бережливость, установка, сборка

**Не мешать и не грузить**
- «Не мешать в развёрнутых окнах»: если сверху развёрнутое/полноэкранное окно (видео, игра),
  снег над ним не рисовать и не считать (оставить только над окнами поверх него).
  Когда показывать нечего — тикать 4 раза в секунду.
- Батарея / экономия (`GetSystemPowerStatus`): меньше снега, ≤ 30 кадров/с.
- Блокировка экрана (`WTSRegisterSessionNotification`) — стоп.
- Выключены анимации Windows (`SPI_GETCLIENTAREAANIMATION`) — не показывать падающий снег.
- Частота: фиксированная (30/60/120/144) или «как у монитора» — частота каждого монитора
  через `EnumDisplaySettings(ENUM_CURRENT_SETTINGS).dmDisplayFrequency`; цикл тикает на самой
  высокой, медленные мониторы пропускают кадры.

**Установка без прав администратора** (прямо в exe)
- Первый запуск скачанного файла: спросить «Установить?» (MessageBox с `MB_TOPMOST|MB_SETFOREGROUND`,
  иначе окно спрячется!). Копировать exe в `%LOCALAPPDATA%\Programs\<Имя>`, ярлык в «Пуск»
  (WScript.Shell), автозапуск `HKCU\...\Run`, запись удаления
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\<Имя>` с
  `UninstallString = "exe --uninstall"`.
- Удаление: закрыть запущенную копию (найти главное окно по классу → `WM_CLOSE`), убрать всё,
  папку удалить через `cmd /c timeout 2 & rmdir` (exe не может удалить сам себя).
- Single-instance через именованный `Mutex`; перед запуском установленной копии освободить его.

**Сборка в один файл**
```xml
<RuntimeIdentifier>win-x64</RuntimeIdentifier>
<SelfContained>true</SelfContained>
<PublishSingleFile>true</PublishSingleFile>
<IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>
<EnableCompressionInSingleFile>true</EnableCompressionInSingleFile>
<ApplicationIcon>app.ico</ApplicationIcon>
```
`dotnet publish -c Release -o publish` → один exe ~37 МБ без установленного .NET.
Trimming не включать (Vortice/COM-интероп). Без подписи кода SmartScreen предупредит —
это нормально для маленьких разработчиков.

## Как проверять и общаться с агентом (важно!)

1. **После каждого этапа запускайте и смотрите сами.** Пишите конкретно:
   «горб при смахивании маленький», «падает цепочкой точек», «гирлянды тусклые».
2. **Лучшее средство обратной связи — короткое видео экрана** (Win+Alt+R или NVIDIA).
   Агенту можно дать задание разобрать его на кадры через ffmpeg и сравнить.
3. **Просите замер нагрузки** после каждого этапа (CPU за 20–30 с, с прогревом 10 с —
   первые секунды всегда тяжелее). Если выросло — пусть профилирует по частям кадра
   (обход окон / симуляция / отрисовка / EndDraw / Present) через переменную окружения.
4. Не принимайте «готово» без запуска: пусть агент пишет, что проверено, а что нет.

## Частые грабли (сэкономят часы)

| Симптом | Причина / решение |
|---|---|
| Снег не виден, CPU 0 % | в настройках осталась пауза |
| Высокий CPU от сугробов | PathGeometry каждый кадр → GeometryRealization + отдельный слой + редкие перестройки |
| Высокий CPU в простое | EnumWindows каждый кадр → WinEvent-хуки |
| Смахнутый снег = «пиксели»/цепочки | сетка-«песок» с мелкими ячейками; лучше мягкие комья из эллипсов |
| Комья угловатые | не использовать многоугольники; группа перекрывающихся эллипсов |
| Ком сразу прилипает обратно | игнорировать исходный сугроб ~0,3 с |
| Ложная «тряска» при разворачивании окна | прыжок за один скан > ~150 px — не тряска |
| Окно установки не видно | MessageBox без `MB_TOPMOST` прячется за окнами |
| Живые обои не показываются на 24H2 | новый способ: дочернее окно Progman под SHELLDLL_DefView |
| Гирлянда «лежит» на крыше дома | вешать вдоль нижней кромки свеса, не по скату |

## Готовые запросы для Codex по этапам (копируйте по одному)

1. «Сделай этап 1 из гайда: прозрачные click-through оверлеи на всех мониторах через
   D3D11+D2D+DirectComposition, снег спрайт-батчем, трей-меню, пауза, 3 режима, ветер,
   горячие клавиши Ctrl+Alt+Shift, настройки в JSON. Собери и замерь CPU.»
2. «Этап 2: сугробы-карты высот на краях окон/панели задач/низа экрана, WinEvent-хуки,
   видимые отрезки с учётом Z-порядка, GeometryRealization, отдельный слой сугробов,
   тряска и осыпание при сворачивании. Замерь CPU до и после.»
